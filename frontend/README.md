# Paradox Edge Trader frontend

React, TypeScript, and Vite operator interface for the seven-agent community.

## Frontend-only preview

Use Node 22.12+ and npm 10.9.9. From this directory:

```sh
npm ci
npm run dev
```

Open the local address Vite prints. **Do not start the Python API or engine for this preview.** The API's existing startup lifecycle starts its scheduler if independently launched.

The default mode uses labeled local fixtures for agent and portfolio examples and reads the actual imported collection locally on the Library page. All backend writes remain blocked. No environment file, accounts, or keys are needed. Inspect Wake Choices to select an agent and demonstrate a choice window. Your demonstration is local UI state, not an agent decision or executed activity.

Library search returns bounded excerpts with original filenames, hashes, and page/paragraph/line locators. The extracted corpus loads lazily rather than entering every dashboard view or agent wake. Originals remain byte-for-byte in the private repository. A static frontend build contains this private extracted collection; do not publicly distribute it without deciding which sources can be shared.

Costs shows clearly labeled synthetic request examples with separate reported, estimated token-only, and unknown figures. It is a read-only local screen in default preview, not an account balance or actual spending report. The prepared backend ledger records request metadata when independently operated; no provider connection is needed to inspect the UI. See [operating-cost notes](../docs/OPERATING_COSTS.md) for coverage, privacy, and optional explicit rates.

Inquiry History reads a deterministic example generated by the actual temporary one-agent mock lifecycle: one Alchemist options position plus inquiries that do not become trades. Inquiry notes, optional proposals, review, broker-confirmed mock fills, positions, and later interpretation remain separate. It adds no execution controls. Protected backend reads and linked review require a server-side `LINEAGE_OPERATOR_TOKEN`; browser login/credential delivery is not implemented in this pilot. Never put that token into `VITE_*` variables. See [idea-lineage notes](../docs/IDEA_LINEAGE.md) for verified behavior and remaining work.

The Agent selector now includes all seven owners, each with private local inquiry examples; only the original Alchemist mock cycle contains orders. Changing owners clears the previous detail immediately. Compact onboarding, independent community gates, and optional runtime inquiry are described in [community onboarding](../docs/COMMUNITY_ONBOARDING.md). The root `scripts/run_offline_arrival.py` is a finite scripted rehearsal, not a live launch or schedule.

Sessions shows an actual-controller, explicitly scripted seven-owner example with two wake rounds, request and limit coverage, neutral progress, and protected owner-local record shapes. The technical `/rehearsal` route remains stable. Offered actions and their reservation ceilings, selected actions and actual outcomes are distinct. Owner-private decision inputs and bounded prior-note context require an explicit read; missing older context remains unavailable. The example uses serial dispatch only for deterministic resource snapshots, with normalized IDs, timestamps and example input hashes.

The screen is read-only and cannot start models. The separate `scripts/rehearsal.py` commissioning CLI uses isolated run stores; real starts require frozen exact assignments, catalog readiness, a chosen budget, a dedicated process key and explicit arming. The dedicated read-only API does not start the ordinary scheduler. See [session-control notes](../docs/REHEARSAL.md) for stop/recovery controls and [decision continuity](../docs/DECISION_CONTINUITY.md) for preserved choices and source context.

Journals provides separate trading, idea and orientation destinations, with Unclassified preserved for older notes. Optional compost originals, chosen distillations, released-source links and private witness accounts are readable without any write or release control. The witness records source-backed activity in its own ledger; exact agent notes remain separately attributed. The local example includes explicitly scripted pre-existing compost and shares the same temporary session source as Sessions. See [compost/witness notes](../docs/COMPOST_WITNESS.md) for active versus archived context and current scope.

Only the exact build-time setting `VITE_RUNTIME_MODE=connected` restores existing backend requests. A `VITE_API_URL` by itself does not enable them. There is no in-app mode switch. Connected operation requires separate configuration and execution-safety work; it is not deployed or enabled by this milestone. Never put private provider/broker keys in `VITE_*` variables.

## Checks

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

Frontend interaction tests run in an isolated DOM with network calls blocked. The Python regression suite and offline fixture-generation check run from the repository root:

```sh
python3 -B -m unittest discover -s tests -v
python3 -B scripts/build_ui_fixtures.py --check
python3 -B scripts/import_library.py --check
python3 -B scripts/build_lineage_fixture.py --check
python3 -B scripts/build_rehearsal_fixture.py --check
python3 -B scripts/build_compost_fixture.py --check
```

To regenerate public persona/menu examples, run the fixture script without `--check`. It does not read configured credentials or private agent records.

See [fixture choice UI notes](../docs/FIXTURE_CHOICE_UI.md) for the actual milestone boundary and [the implementation plan](../docs/CHOICE_UI_PLAN.md) for structure.
