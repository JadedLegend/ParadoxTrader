# ParadoxTrader heartbeat: individual clocks, owner settings in the dashboard

- Agents wake on their own staggered clocks, one wake per agent per slot. Never schedule one gathering of all agents.
- The owner's choices (each agent's OpenRouter model, the key, the daily budget) live in the dashboard Settings page and its `settings_dir`. Do not add server config files for them. Clock settings are different: `choices_per_wake` lives in `/etc/paradoxtrader/heartbeat.json` on the droplet, and changing it is a separate server step after the install. The key is write-only: the UI shows only "Set, ends in …" and never echoes it.
- Budget counts actual charges, not worst cases (`docs/specs/BUDGET_ACTUAL_CHARGES.md`): only a successful request with a provider-reported charge counts that charge. In flight, uncertain, failed (even at $0), never-sent, and unknown or estimated costs keep their full set-aside. Failures never release, because an error can still be billed. Admission, the run summary and the heartbeat's spent check all read the one `counted_usd` helper; `reserved_usd` stays the raw history.
- Budget: lowering it applies at once; raising it applies from the next wake. A model change or a budget raise closes today's run and opens a new segment of the same day that continues the home. Spend is summed across that day's segments.
- Carried-over "already done" markers must be keyed by day, or yesterday's markers make today's wakes look like repeats.
- The store accepts memory references only from earlier rounds of the same day. A carried day has to be taught to that check, or its references are rejected.
- Until the owner has chosen models and a budget, the heartbeat runs clock-only (keeps time, wakes no one, spends nothing). Switching to live dispatch is an explicit owner step.
- Before that switch, build the day manifest against today's live OpenRouter catalog using the seven agent models (`agent_models()`, never the eight-slot `models()` that includes the witness). If the build raises, stay clock-only and fix it first.
- On a failed live wake, restore the clock-only config before diagnosing. A wake refused by the spend guard spends nothing; the cause is usually a catalog shape the guard does not yet read (see provider-key-model-check).
- The witness account stays idle until the witness writes it in prose; the Settings page says so.
- A wake can hold several choices (`choices_per_wake`). Record the slot as woken when choice 1 returns and update it after each later choice, so a restart mid-wake finds the slot done and reruns nothing. A slot must never exceed `choices_per_wake` turns, and a restart must not take turns from later wakes. Moves per wake run 1 to 4, and wake slots times choices may not exceed 96 turns per agent per day (`docs/specs/AGENT_CLOCKS.md`); the bounded test in `tests/test_heartbeat.py` pins both limits.
- A later choice refused before it starts (for example the key cleared mid-wake) ends that wake. It must not raise out of the tick, which would skip the other agents due that minute.
- A skill opened on one move stays at hand for the later moves of the same wake, both choices and activities (journal, inquire, roam, library). At most two stay open, and the skill being opened now counts as one of them, so a third opening carries only the newest earlier skill. Reopening a skill never repeats its text. Open skills are also bounded by `max_input_bytes`: one that does not fit is set down, and the owner's notes are never clipped. When the page is full the oldest is set down first, and the choice list is never dropped. Store only skill names in the move's private context, so a resumed move rebuilds the same text; the skill goes back on the shelf when the wake ends.
- A test fake that simulates a crash must raise after its choice is stored. Raising earlier lets the "earlier wake unfinished" guard fire first, so the test never reaches the crash.
- Changing `choices_per_wake` is a stale-run change like a model change: the open run has too few rounds, so the heartbeat closes it and opens a new segment of the same day. Expect a second `days` row after the change.
- When the owner says "latest <model family>" for a slot, query the OpenRouter model list sorted by `created` and take the newest plain text line of that family. Skip variant lines whose name marks another modality (for example "omni") unless the owner asks for them. Report the chosen id and the rejected alternative.
- A failed wake writes a slot note naming the agent and model, for example "siren on xiaomi/mimo-v2.6-flash: http_rejected". Read that note and the status problems list before blaming the model or the key.
- After the owner says Settings is filled in, verify on the droplet by reading the saved settings through the app's own `OwnerSettings` read, not the UI. Report the count of models and key boxes set per slot. Do not infer "saved" from a page that looked filled.
- A journal choice that names notes the agent cannot condense is a definite failed wake (`invalid_journal_sources`), not an uncertain one. An uncertain wake blocks that agent's later slots, and nothing retries it.
- A wake left pending by a crash is safe to replay: that agent's next slot finishes it first, then starts its own wake. Do not block the slot on it. Test this with a pending wake followed by a normal tick.
- Day runs raise `max_output_tokens` to 4096 in the manifest. Models that think first count thinking toward `max_tokens`, so 1024 leaves no room for the answer. Full rehearsals stay at 1024 and reject any higher value.
- When a day-run reply is cut off, read that call's thinking-token count before raising the cap again. If the model thinks at length, swap it for a model whose replies finish (Oracle's cut-offs stopped after a switch to the model Weaver runs on, which had zero cut-offs that day).
- The Heartbeat dashboard page is read-only. It is built by `GET /api/heartbeat` in `deploy/private_dashboard.py` on `Heartbeat.status()` (`core/runtime/rehearsal/heartbeat_view.py`). It must never wake an agent, change state, show a key, or show a private note. Errors return `{"error": "heartbeat_unreadable"}` with no paths; a missing config returns a plain "not set up" message. Keep any new field to this rule.
- Adding an agent choice (for example a call, inquiry or options read) means extending `CHOICE_INSTRUCTIONS` in `core/runtime/rehearsal/controller.py`, which is a `.replace` chain on `LEGACY_CHOICE_INSTRUCTIONS`. Do not add a second prompt. Market, options and feed data are read once in `_new_decision_context` and committed into the private context ("Read once and committed with the context, so a resumed wake and its inquiry see exactly what this choice saw"). Never re-read them when the message is built in `_choice_messages`, or a resumed wake sees a different price than the one it was offered.
- Agent-facing instructions (choice prompts, call and inquiry text) describe a choice's shape with named fields and allowed values, never a worked example with real values such as a ticker, a direction and a horizon. Every agent copies the example, so all seven drift into the same choice. Read the prompt as an agent would before shipping it.
